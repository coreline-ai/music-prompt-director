# 출력·가사·수정·검수

## 사용자에게 줄 것
필요한 만큼만 다음 순서로 쓴다. 전문 용어에는 곡에서의 역할이 있어야 한다.

**방향/가정:** 사용자의 조건과 제안한 요소를 구별하는 2–4문장 정도. 선택 이유는 한 문장으로 충분하다.
**계획:** 음악 성격, 유용한 목표값, 악기 역할, 보컬, 톤/공간의 핵심을 짧게.
**구간:** `구간 | 감정·밀도 | 진입/퇴장·보컬 | 전환·처리`의 작은 표 또는 간결한 목록.
**복사문:** 스타일·전개·필수/금지 조건이 일치하는 하나의 자족적인 입력. 설명·가사·검수 메모는 섞지 않는다.
**가사:** 제공된 가사 또는 명시 요청으로 새로 쓴 가사만 별도 블록. 필요 없으면 이 항목 자체를 생략.
**검수/제약:** 보존한 중요한 조건, 입력 준비 상태, 실제 생성 후 확인할 것. 매번 장문의 면책 문구는 불필요하다.

범용 입력은 장르/목적 → 주역/그루브/보컬 → 구간 변화 → 대상별 처리 → 중요한 회피 조건의 자연스러운 문단으로 작성할 수 있다.
강제 JSON이나 별도 negative 필드를 발명하지 않는다. 중요한 제외 사항은 일반 문장에 담는다.
한국어 설명과 영어 복사문의 의미를 대조한다. 사용자 언어 지시가 있으면 그것을 따른다.

## 가사 상태
- 사용자 가사는 철자·띄어쓰기·줄바꿈·구간 표기를 포함해 그대로 보존한다. 요청 없는 번역·축약·후렴 추가도 변경이다.
- 제공 가사에 맞추려면 우선 구간 계획/음가를 조정한다. 그래도 길이 요구와 충돌하면 바꿀 부분을 확인한다.
- 새 가사 요청이면 감정 곡선과 구간 수에 맞춰 독창적으로 쓰고 스타일 지시와 분리한다. 다른 곡의 가사를 전용하지 않는다.
- 보컬곡이라고 자동으로 새 가사를 쓰지 않는다. 가사 필수 타깃인데 없다면 `가사 입력 필요`; 선택적인 범용 계획이라면 `가사는 미작성`으로 설명한다.
- 가사가 들어갈 자리에 안내 문구를 복사용 가사처럼 넣지 않는다.

## 후속 수정
1. 이전안에서 유지할 조건을 찾는다. 요청한 차원(예: 공간/템포/편성/감정)만 변경한다.
2. 연쇄 영향이 있을 때만 설명한다. 템포 변경은 마디당 시간에 영향을 줄 수 있지만 공간감 수정이 조성/가사를 바꾸는 이유는 아니다.
3. 수정한 항목과 유지한 항목을 짧게 표시하고 필요하면 갱신된 복사문 전체를 제공한다.
4. 이전안과 새 입력을 나란히 대조한다. 원문이 없으면 수정할 프롬프트를 요청하며 새로운 곡을 임의로 만들어 대체하지 않는다.

## 검수 질문
| 검사 | 확인할 실제 결과 |
|---|---|
| 의도/조건 | 사용자의 금지·고정 조건이 계획과 복사문 모든 구간에서 유지되는가? |
| 차원/대상 | 공간·톤·발성 지시의 대상이 구별되고 동일 대상/시점에서만 모순을 판단했는가? |
| 구조 | 주역의 변화, 악기 진입/퇴장, 전환과 끝맺음이 곡 목적에 맞는가? |
| 숫자 | 시간 합계와 마디/BPM의 단위가 맞는가? 숫자가 불필요하면 생략했는가? |
| 효과 | 목적 없는 처리, 임의의 프리셋, 금지된 악기/목소리가 덧붙지 않았는가? |
| 모델 | 음악적 요청과 실제 입력 규격을 구별했는가? 미확인 필드를 발명하지 않았는가? |
| 가사/수정 | 제공 원문과 유지 조건이 그대로인가? 필요한 가사가 미완성인 상태를 표시했는가? |
| 정직성 | 텍스트 자체 검토를 실제 오디오/독립 전문가/자동 발견 검증으로 표현하지 않았는가? |

결함이 있으면 관련된 부분을 고치고 같은 기준으로 다시 본다. 의미 있는 문제가 없는데 점수를 올리려고 재작성하거나 효과를 추가하지 않는다.
서로 다른 요청이 악기·리듬·감정·전개·엔딩은 같고 형용사만 다른 결과로 수렴하면 목적부터 재검토한다.

`최적`은 현재 의도·제약에 잘 맞도록 설계했다는 뜻이지 모든 생성기에서 최상의 소리가 보장된다는 뜻이 아니다.
실제 생성 후에는 목적에 따라 길이/템포, 가사 전달, 루프 경계, 채널별 피크·클리핑, 모노 재생 등을 확인할 수 있다.
여기서는 그 확인이나 오디오 수정을 실행한 것처럼 말하지 않는다.
